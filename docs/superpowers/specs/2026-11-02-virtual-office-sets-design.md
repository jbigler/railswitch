# Virtual Office: swappable sets

Design for D153, agreed with the user on 2026-11-02. Builds on the office
(D144–D148, refreshed in D150), the dashboard terminals (D149), the
whiteboard (D151) and the PR page (D152).

## Intent

The dashboard's 3D view of a project is called the Virtual Office: its
route, files, page title and button. Its art comes from a **set**: one
aesthetic's models plus a short description of its atmosphere. Today's
art becomes the built-in set `cyberpunk`; more sets, built in or added on
one machine, switch the whole look without touching the layout.

A prop is identified by a base name and its dimensions. railswitch owns
that list; a set supplies models that match it.

Decisions taken with the user:

- Sets are built in Blender to a strict contract: a piece must match its
  declared size, and a set that doesn't is refused (not scaled to fit).
- Sets live built in (embedded) or in a folder on the machine, installed
  by a CLI command that checks them; the active set is chosen per machine.
  Not packages, libraries or per project.
- The contract is a name and dimensions. Colliders, moving parts and
  accent materials are optional; the office does without what a piece
  lacks.
- A piece the set lacks is a plain box at the declared size.
- A set carries its look (colours, fog, lights' colours and strength,
  bloom, scanlines), not its own light rig.
- The built-in set is named `cyberpunk`. The feature is "Virtual Office".

## The piece list

`internal/web/static/office/kit/pieces.json`, generated by
`tools/office-kit/` from the `cyberpunk` set and checked in:

```json
{
  "version": 1,
  "pieces": {
    "Furn_ParrotPerch": {
      "size": [0.62, 1.42, 0.48],
      "anchor": "floor",
      "points": { "bar": [0, 1.284, 0] },
      "extras": ["collider"]
    }
  }
}
```

- `size`: the bounding box's x (width), y (height), z (depth) in meters,
  in the piece's own frame (front +Z).
- `anchor`: where the origin is. `floor`: on the floor at the footprint's
  centre (box y from 0 to height, x and z centred). `wall`: at the
  centre, back against the wall (box centred in x and y, z from 0 to
  depth). `ceiling`: at the ceiling (box y from -height to 0, x and z
  centred). These are today's conventions (`docs/office-kit.md`).
- `points`: named positions in the piece's frame the layout places things
  at or on (a desk's `top`, the perch's `bar`, a screen's `screen` as its
  centre plus a `screen_size` [w, h]). The layout reads these, never
  literals.
- `extras`: what the `cyberpunk` piece has beyond its shape: `collider`,
  `parts` (with the node names, `"parts": ["Door_L", "Door_R"]`), `accent`.

`version` changes only when the list changes in a way that breaks sets
(a piece's size, anchor or points); adding a piece doesn't change it.

A set's piece must match `size` within ±0.02 m per axis and have its
origin at `anchor` (the box's extent from the origin within ±0.02 m of the
anchor's rule). `points` are the contract too but can't be read from a
mesh: they are documented, and the preview (below) draws them.

## A set

A folder:

```
<name>/
  set.toml
  <Piece>.gltf, its .bin and textures
```

```toml
schema = 1
name = "cabin"          # [a-z][a-z0-9-]{0,30}
version = 3             # the set's own version
pieces = 1              # the pieces.json version it was built for
description = "Pine, wool and lamplight"

[look]                  # each key optional: the cyberpunk value otherwise
accent = "#e8a04a"
secondary = "#7aa36b"
background = "#1b1612"
fog = "#1b1612"
fog_density = 0.02      # 0: no fog
ambient = "#fff1dd"
ambient_intensity = 0.6
key = "#ffd8a0"
key_intensity = 1.2
bloom = 0               # 0: off
scanlines = false
```

`set.toml` is strict (unknown keys refused), colours `#rrggbb`, numbers in
documented ranges (intensities 0..10, fog_density 0..1, bloom 0..3).
`cyberpunk`'s `set.toml` holds today's values exactly.

Built-in sets: each folder under `static/office/sets/`; their names are
reserved. Installed sets: `<data>/office/<name>/` (the data dir is
`~/.local/share/railswitch/`), written only by `office set add`.

## Commands

- `railswitch office set check <dir> [--json]`: reads the folder as
  hostile and writes nothing. Folder rules (refusal of the whole set):
  symlinks (the folder included), non-regular files, more than 1,000
  files, a file over 16 MiB, more than 256 MiB in all, a file that is
  neither `set.toml` nor a `.gltf` named after a piece nor referenced by
  one of those glTFs, a glTF URI that is absolute, has a scheme other than
  `data:`, or leaves the folder. Per piece: `ok`, `missing`, or `refused`
  with a reason naming the numbers (`Furn_Desk: 1.62 × 0.76 × 0.80 m, the
  list says 1.60 × 0.75 × 0.80 (±0.02)`); a `.gltf` whose name isn't in
  the list is refused; a glTF that doesn't parse, has no mesh, or an
  accessor without `min`/`max` is refused. `set.toml` errors are reported
  the same way. Exit 0 only when nothing is refused. `--json`:
  `{name, version, pieces, look, results[]{piece, status, reason, size}, errors[]}`.
- `railswitch office set add <dir>`: check; any refusal refuses the add.
  Copies the set to `<data>/office/<name>/` (a temp dir under
  `<data>/office/` renamed over the old one) with `index.json`
  `{files: {<path>: <sha256>}, pieces: [names], added}`. A built-in
  name is refused. Re-adding replaces.
- `railswitch office set ls [--json]`: built-in and installed sets:
  `{active, sets[]{name, source ("builtin"|"installed"), version, pieces,
  present, missing, status ("ok"|"stale"|"broken"), description, look,
  have[]{piece, extras[]}}}` (`have` only for the active set: what the
  page needs). `stale`: built for another `pieces` version; `broken`: an
  installed set whose `index.json` or files don't verify.
- `railswitch office set use <name>`: `dashboard.toml` `[office] set`.
  Refuses an unknown, stale or broken set.
- `railswitch office set rm <name>`: removes `<data>/office/<name>/`
  (exact path); refuses a built-in; when it was active, `[office] set` is
  removed (the default is `cyberpunk`).

`office` and `set` are new command words; `office set` reads go under D40
(`--json`, schemas in `docs/json.md`); every `e.flags` gets a `--help`
synopsis.

## The dashboard

- `GET /office/set.json`: the active set from `railswitch --json office
  set ls`: `{name, base, version, look, have}` where `base` is
  `/static/office/sets/<name>/` (built in) or `/office/sets/<name>/`
  (installed). An active set that is missing, stale or broken falls back
  to `cyberpunk` with `fallback: "<reason>"`, which the page shows as a
  banner.
- `GET /office/sets/{name}/{path...}`: an installed set's file, only when
  `{path}` is in its `index.json`, and only when the file's sha256 still
  matches (else 404). Read with `safefile`-like rules: regular file,
  no symlink, under the set's directory. Cookie and Host as every request.
- Machine page: an "Office set" row: the sets from `office set ls`, a
  select, applied by a `office set use` job.
- The worktree page header and the project page link "Virtual Office"
  (today "office"/"cyberpunk" wording).

## The page

- `office.js` fetches `/office/set.json`, then `loadOfficeKit(set,
  pieces, names, loader)` (`kit.js`).
- `kit.spawn(name)`: the set's model when `have` lists it; otherwise a box
  of the piece's `size`, placed by its `anchor`, material
  `RS_Placeholder` (light grey, darker edges), its `userData.missing`
  set (tooltips say "missing in <set>"). A name not in `pieces.json`: a
  red box and a console error.
- Colliders: a piece's `_COL` nodes; if it has none and the list's
  `extras` include `collider`, one box of its `size`.
- Parts: `animate`, the roamers and the elevator act on the nodes found;
  missing ones do nothing (a pet glides, an android doesn't type, the
  elevator's doors don't open).
- Accent: `setAccent`/`setSecondary` change materials named as today
  (`RS_Neon_Accent`, …): a set opts in by naming its materials so.
- `kit.point(piece, name)` returns a point from `pieces.json`; `rooms.js`
  uses it for every height today written as a literal (desk and table
  tops, the perch bars, screens).
- Look: `world.js`/`film.js` take background, fog, ambient, key light,
  bloom and scanlines from `set.look` instead of constants; light
  positions stay.

With `cyberpunk` the office must look as it does today.

## Blender

- `build_all.py` writes the models to `static/office/sets/cyberpunk/`
  and `pieces.json`: each piece's size from its exported bounding box,
  its anchor from its category (the conventions above), its points from
  empties named `<piece>_PT_<point>` (dropped from the glTF), its extras
  from its `_COL` nodes, named parts and `RS_` accent materials.
- The points the layout needs today become such empties.
- `stub_set.py <out.blend>`: a scene with a wireframe box of the right
  size and anchor for every piece and its point empties, to model a new
  set inside.

## Errors

- `check`/`add` name each problem with its piece and numbers.
- The page: an active set that can't be used falls back to `cyberpunk`
  with a banner; a model that fails to load becomes its box and a console
  error.

## Testing

Unit (no podman, network or browser):

- `internal/office`: glTF bounds on hand-written glTFs (node rotation,
  scale, nested nodes, several meshes, an offset origin, a `data:` buffer
  URI); folder refusals (symlink, `..` URI, absolute URI, oversize file,
  stray file, too many files); per-piece results (ok, off by 3 cm, wrong
  anchor, unknown name, missing); `set.toml` strictness and ranges.
- `pieces.json` against the `cyberpunk` set: every piece's bounds and
  anchor match, every model has an entry (the generator can't drift).
- CLI: `check` exit codes and JSON; `add` (new, replace, built-in name
  refused); `ls` (built-in, installed, stale, broken after a file edit);
  `use` (unknown, stale refused); `rm` (built-in refused, active cleared).
- Dashboard: `set.json` (active, fallback); serving: indexed file ok,
  unindexed 404, edited file 404, `..` 404; the rename (routes answer at
  `/virtual-office/<set>` for a built-in and an installed set, an unknown
  set 404, the bare path to the active set).

Manual: the office with `cyberpunk` looks as before (screenshots before
and after); a test set with three pieces, the rest boxes, and another
look; the Machine page picker.

## Out of scope

- Sets as packages, from libraries, or per project.
- Scaling models to fit; sets with their own light rigs or layouts.
- A `--watch` for rebuilding while modelling.
- More built-in sets (later, as folders beside `cyberpunk`).
